# 1. Использование Yandex Managed Service for Kubernetes

**Yandex Managed Service for Kubernetes** (Yandex Kubernetes Engine, YKE) предоставляет мощный инструмент для развертывания и управления контейнеризированными приложениями с высокой степенью отказоустойчивости, автоматического масштабирования и доступности. Размещая кластер Kubernetes в трёх **Availability Zones (AZ)**, можно добиться максимальной устойчивости к сбоям и равномерного распределения нагрузки.

## Отказоустойчивость

Использование трёх **Availability Zones** в Yandex Cloud позволяет распределить узлы кластера Kubernetes (как master, так и worker nodes) по разным физическим локациям внутри одного региона. Это обеспечивает:

- **Автоматическое восстановление**: При выходе из строя одной зоны кластер продолжает работать за счёт узлов в других зонах.
- **Резервирование компонентов control plane**: Master-узлы распределяются по зонам, что гарантирует бесперебойную работу управляющих компонентов Kubernetes (API Server, Scheduler, Controller Manager и т. д.).
- **Устойчивость к авариям инфраструктуры**: Даже при полном отказе одной AZ приложения остаются доступными благодаря репликации Pod'ов и сервисов в других зонах.

## Масштабирование

**Yandex Managed Kubernetes** поддерживает горизонтальное масштабирование как на уровне кластера, так и на уровне приложений:

- **Автомасштабирование узлов (Cluster Autoscaler)**: Кластер автоматически добавляет или удаляет worker nodes в зависимости от нагрузки, распределяя их по доступным зонам для балансировки ресурсов.
- **Горизонтальное масштабирование Pod'ов (HPA)**: Kubernetes может динамически увеличивать или уменьшать количество реплик приложений, учитывая распределение по зонам для минимизации риска перегрузки.
- **Равномерное распределение нагрузки**: Сервисы балансировки Yandex Cloud (Network Load Balancer, Application Load Balancer) автоматически направляют трафик на работающие экземпляры приложений во всех доступных зонах.

## Доступность

Развёртывание в трёх AZ обеспечивает высокий уровень доступности (**SLA до 99.95% и выше**):

- **Геораспределённые поды**: Stateful- и Stateless-приложения могут быть развёрнуты с anti-affinity правилами, гарантируя, что Pod'ы не будут сосредоточены в одной зоне.
- **Отказоустойчивое хранилище**: Использование сетевых дисков (network SSDs) с автоматической репликацией между зонами или региональных Persistent Volumes повышает надёжность хранения данных.
- **Резервирование сетевой инфраструктуры**: Встроенные механизмы Yandex Cloud обеспечивают бесперебойную маршрутизацию трафика даже при сбоях в одной из зон.



# 2. Использование Managed Services for PostgreSQL

**Managed Services for PostgreSQL** в Yandex Cloud обеспечивает высокий уровень отказоустойчивости за счёт распределения ресурсов кластера между тремя **Availability Zones (AZ)**. При таком подходе:

- Основная реплика PostgreSQL автоматически размещается в одной AZ
- Синхронные реплики разворачиваются в двух других зонах доступности
- В случае сбоя в одной из зон, сервис автоматически переключает работу на оставшиеся реплики
- Данные постоянно реплицируются между всеми узлами кластера, обеспечивая консистентность
- Механизм автоматического восстановления минимизирует время простоя, сохраняя доступность сервиса даже при выходе из строя целой зоны доступности

## Горизонтальное и вертикальное масштабирование

Сервис предоставляет гибкие возможности масштабирования для адаптации к изменяющейся нагрузке:

### Вертикальное масштабирование:
- Возможность оперативного изменения вычислительных ресурсов (vCPU, RAM) для каждой реплики
- Масштабирование хранилища без прерывания работы сервиса
- Настройка производительности под изменяющиеся требования нагрузки

### Горизонтальное масштабирование:
- Добавление дополнительных реплик для распределения read-нагрузки
- Возможность создания реплик в разных AZ для географического распределения
- Автоматическая балансировка запросов между репликами

## Обеспечение высокой доступности

Архитектура в трёх AZ гарантирует доступность сервиса на уровне **99.9% и выше**:

- Автоматический failover при обнаружении проблем с основной репликой
- Мониторинг состояния всех компонентов кластера в реальном времени
- Резервное копирование с возможностью восстановления на определённую точку во времени
- Возможность настройки времени начала и периода хранения backup'ов
- Шифрование данных как при передаче, так и при хранении

Сервис берёт на себя все операции по обслуживанию инфраструктуры, включая:
- Обновления ПО
- Патчи безопасности
- Оптимизацию производительности

Это позволяет сосредоточиться на разработке приложений, не беспокоясь об инфраструктуре.



# 3. Использование Application Load Balancer (ALB)

**Application Load Balancer (ALB)** в Yandex Cloud обеспечивает высокую отказоустойчивость за счёт распределения входящего трафика между серверными группами, развёрнутыми в трёх **Availability Zones (AZ)**.

## Ключевые возможности

- **Распределение нагрузки между зонами**
  ALB автоматически направляет запросы только на работающие инстансы, исключая из ротации неисправные узлы.

- **Автоматическое восстановление маршрутизации**
  При выходе из строя одной или даже двух зон балансировщик продолжает обслуживать трафик через оставшиеся доступные AZ.

- **Health Checks**
  Регулярные проверки работоспособности backend-серверов позволяют оперативно обнаруживать и исключать проблемные узлы.

Таким образом, даже при потере целой зоны доступности нагрузка автоматически перераспределяется, минимизируя влияние на пользователей.

## Горизонтальное масштабирование

ALB позволяет эффективно масштабировать приложения, адаптируясь к изменяющейся нагрузке:

### Основные механизмы масштабирования
- **Динамическое добавление backend-серверов**
  Можно увеличивать количество инстансов в серверных группах без изменения конфигурации балансировщика.

- **Автоматическое масштабирование**
  Интеграция с Yandex Compute Auto Scaling позволяет ALB работать с группами виртуальных машин, которые автоматически расширяются или сокращаются в зависимости от нагрузки.

- **Распределение нагрузки между серверными группами**
  Возможность балансировки трафика между разными версиями приложения или микросервисами.

> Данные возможности позволяют приложению справляться с пиковыми нагрузками и экономить ресурсы в периоды снижения трафика.

## Обеспечение высокой доступности

Архитектура с ALB в трёх AZ гарантирует доступность сервиса на уровне **99.95% и выше**:

### Особенности реализации
- **Распределённая инфраструктура**
  Ноды балансировщика развёрнуты в нескольких зонах, что исключает единую точку отказа.

- **Поддержка нескольких протоколов**
  HTTP/HTTPS, gRPC, WebSocket - балансировка как веб-трафика, так и API-запросов.

- **Гибкая маршрутизация**
  Настройка правил перенаправления, A/B-тестирование, blue-green-развёртывание без простоев.

- **Защита от DDoS**
  Встроенные механизмы Yandex Cloud помогают минимизировать влияние атак на доступность сервиса.



# 4. Использование API Gateway в Yandex Cloud

## Обеспечение отказоустойчивости в трёх Availability Zones

API Gateway в Yandex Cloud проектировался как региональный сервис с автоматическим распределением нагрузки между тремя **Availability Zones (AZ)**, что обеспечивает:

**Распределённая архитектура**
Компоненты сервиса автоматически размещаются во всех трёх зонах доступности региона

**Автоматическое переключение при сбоях**
При выходе из строя одной AZ сервис продолжает работу через оставшиеся зоны без вмешательства администратора

**Резервирование на уровне инфраструктуры**
Все критические компоненты (управляющая плоскость, плоскость данных) дублируются между зонами

## Возможности масштабирования

API Gateway обеспечивает эластичное масштабирование для обработки переменных нагрузок:

**Автоматическое горизонтальное масштабирование**
Динамическое изменение количества рабочих узлов в зависимости от нагрузки

**Неограниченная пропускная способность**
Архитектура позволяет обрабатывать практически любое количество API-вызовов

**Интеграция с масштабируемыми бэкендами**
Поддержка подключения к:
- Compute Auto Scaling
- Managed Services
- Serverless Containers

## Гарантии высокой доступности

Развёртывание в трёх AZ обеспечивает доступность **99.95%**:

**Бесперебойные обновления**
Обновления выполняются поочерёдно по зонам без прерывания работы

**Мониторинг и самовосстановление**
Постоянный контроль работоспособности и автоматическое восстановление

**Глобальная балансировка**
Развёртывание в нескольких регионах с маршрутизацией в ближайший доступный

## Дополнительные преимущества

**Единая точка входа**
Централизованное управление всеми микросервисами

**Встроенная безопасность**
- TLS-termination
- Ограничение частоты запросов

**Кэширование ответов**
Снижение нагрузки на бэкенд-системы

API Gateway в Yandex Cloud устраняет необходимость самостоятельного развёртывания и обслуживания инфраструктуры для API, предоставляя готовое отказоустойчивое и масштабируемое решение с гарантированной доступностью.
